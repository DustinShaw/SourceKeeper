源管家 使用方法

绿色单文件 exe，双击即用图形界面（不弹控制台黑窗）。 命令行为高级用法：需用源码 python injector.py <参数> 运行（打包后的 exe 只出图形界面）。 本文按「我要做什么」组织，可直接按场景查阅。

🎉 当前版本：1.2.0（语义化三段式：主版本.次版本.修订号）。主窗口与所有对话框的标题栏都带版本后缀， 例如 D:\myrepo — 源管家 v1.2.0，提示弹窗也会自动补上——想确认版本看标题栏即可。

两种可执行文件（同一份源码产出，详见文末）： 源管家 v1.2.0.exe（Win10+，Qt6） · Win7 版按需构建，不随每个版本发布（最新为 源管家 v1.0.1-Win7.exe）

0. 第一次使用

  1. 双击 源管家 v<版本>.exe（本版为 源管家 v1.2.0.exe；版本号是三段式 主.次.修订）。
  2. 点「选择…」选中仓库目录（里面应有配置文件和 py/ 文件夹）。
  3. 配置文件一般留空即可——程序会自动识别（主窗口状态标签显示「已加载 xxx.json · 站点 N 个」即成功；窗口标题为「仓库路径 — 源管家 v<版本>」，版本号在所有标题栏与「ℹ 关于」里都能看到）。
  4. 如果你的配置文件不是自动识别到的那一个：点「配置文件」框右侧的 ▼，下拉直接列出仓库目录里的全部候选 JSON（py.json 优先），点选即加载；也可以手动输入文件名（如 12.json）后回车，或点「自动识别」重试。切换仓库目录后下拉候选会自动刷新。

以后每次启动会自动加载上次的仓库目录，无需重复选择。

场景 1：注入新爬虫（.py → 配置）

注入一个/几个文件

  1. 点「📄 注入文件」，在文件框里可多选；也可以直接把 .py 文件拖进主窗口完成注入。
  2. 选中的文件出现在下方「待注入列表」（列表空着时会显示操作引导，告诉你这三种加法；双击列表项可改 key / name）。
  3. 看情况调整「全局开关」（可筛选 / 速搜 / 可搜索）。type 不用管——注入 .py 时已按标准规则自动推断为 3（Spider）；开关里的 type 只在条目自身没有 type 时才兜底，不会覆盖已有站点的 type。
  4. 点「💾 写入配置」→ 完成（自动备份原配置）。
  • 文件在仓库外？勾选「仓库外文件复制到 py/」，程序会先复制再登记。
  • 若 py/ 里已有同名脚本：内容完全相同 → 直接复用（不重复拷贝）；内容不同 → 自动改名 x_2.py（再冲突则 x_3）并让条目指向新名，绝不覆盖你已有的脚本。
  • 缺 class Spider 的文件会被跳过并在日志里说明。
  • 依赖会跟着一起进仓库：若主 .py 里 import / require 了同目录的其它 .py、.js、.drpy，注入（或合并导入）时会一并搬进 py/ 并改写成相对引用——配置上传到电视后影视仓照样找得到全部依赖，源不会失效。遇到同名但内容不同的文件会自动改名 x_2 并同步改写主文件里的引用，不会覆盖你已有的脚本。日志里会列出搬了哪些文件。

批量注入 py/ 目录里所有未注册的

  1. 点「🔍 扫描目录」。
  2. 扫描结果直接进待注入列表；同时日志会反向校验已注册条目的 .py 是否还在：
  3. ✗ 缺失 .py：key（api）对应文件不存在 → 见场景 5
  4. ✓ 已注册 N 个站点的 .py 文件均存在 → 一切正常
  5. 点「💾 写入配置」。

写入前程序自动按 key / api 查重，重复的不会重复登记。

添加"直连 CMS"源（没有 .py 的那种）

有些源不是爬虫脚本，而是一个 JSON 接口地址（type: 1），比如苹果 CMS 的 https://xxx.com/api.php/provide/vod。

  1. 点主窗口工具栏「➕ 添加直连」。
  2. 在弹出的输入框里粘贴 API 地址（一行一个也可以，粘贴多行会逐个登记）。
  3. 程序自动：推断 type = 1、按域名生成 name、生成一个唯一 key → 条目进入待注入列表。
  4. 双击条目可改 key / name；点「💾 写入配置」落盘。

name / key 可以随便改，但 key 一旦写进配置就不建议再动（APP 可能已用它做了缓存/排序）。

场景 2：管理已有站点

点主界面「⚙ 管理站点」打开管理列表（10 列：name / api / 类型 / 筛选·快搜·搜 / 成人 / 短剧 / 直播 / 可达 / 禁用 / 资源；key 在编辑弹窗里可见，不单占一列）。搜索无结果时，表格中央会显示「没有匹配的站点」。

列表顶部右侧有过滤下拉框（全部 / 直连 CMS(1) / Spider(3) / XML(0) / 目录(4) / 🔞 仅成人 / ⚠️ 仅需代理 / ⛔ 仅失效源），可按源类型快速只看某一类；它与左侧搜索框是叠加关系（先搜关键字、再筛类型）。「仅需代理」需先点底部「🌐 网络体检」跑一遍；「⛔ 仅失效源」需先跑过「🩺 源测活」或 URL 可达性检测，且只认明确失效的源（未检测过的不算）。

贴心行为：程序会记住上次的仓库目录（下次打开自动加载）、管理列表的窗口大小、列宽和排序方式。有暂存未写入的更改时，计数行会显示红色「● 未保存更改」；此时直接关闭窗口会询问「保存 / 放弃 / 取消」。表格各列按内容自适应（宽度贴合内容、不留多余空白），均可拖动表头边界调整；手动拖过的列会按你的设置记住。

删除时的选择：

  • 不勾选（默认）：只删配置项、保留 .py —— 以后想再加回来，重新注入即可。
  • 勾选：连 .py 一起删，删除前自动备份到 py_trash/；若别的站点还在用同一个 .py，会自动跳过不删。

「保存并写入」前，你的编辑/删除都只是暂存；不保存直接关窗口 = 什么都没发生。 例外：「禁用选中 / 启用选中」点下去就立即写盘（自动备份）。

场景 2b：把当前排序写进配置文件（⇅ 排序写回配置）

点列头排序只改变显示顺序，配置文件里 sites 的顺序没动。想让这个顺序真正落盘（例如让某些源排在前面、被宿主程序优先使用，或把失效/缺文件的源集中排到末尾）：

  1. 先排好你想要的顺序 —— 点列头（如按「类型 / 直播 / 成人 / 可达 / 资源」列，再点一次切换升降序）；也可以先用搜索框或过滤下拉框只留下想排的那批；
  2. 点底部第 2 行的 ⇅ 排序写回配置 ；
  3. 确认框会写明「位置发生变化 N 条」（若本次被搜索/过滤隐藏了条目，也会写明「隐藏 M 条保持原位不动」）→ 点「⇅ 写回配置」。

要点：

  • 只动可见的那部分：隐藏条目的位置不动（槽位填充），不会把它们甩到末尾；
  • 内容不变：条目逐字保留，// 注释跟着它下面那条走，/ [disabled] / 禁用块原样保留（仍禁用，可随时「启用选中」恢复）；
  • 写入前自动备份到 <仓库>/backups/，随时可回滚；
  • 顺序与文件一致时不会写，只提示；
  • 「成人/短剧/直播检测」运行期间点它会被拦住（提示先停止），避免与检测结果刷新冲突。

顺手的用法：按「可达」或「资源」列把不可达 / 缺文件的源排到一起 → ⇅ 排序写回配置 → 以后打开就在末尾集中复查。

场景 3：给站点做"体检"

打开管理列表后：

① 资源存在性（自动，无需操作）

「资源」列自动后台检测，几秒出结果（列头已由旧版的「文件」改名，因为它现在连直连源一起管）：

显示含义建议
正常（绿）.py 在配置路径上无需处理
缺失（红）文件丢了，该站是死源禁用、删除，或找回文件
已找回（橙）原路径失效，但在仓库别的文件夹找到了同名文件双击该行把 api 改成新路径
远程（灰）api 是 http 的 Spider/远程源，不校验本地文件无需处理
直连（蓝）该站是 type:1 直连 CMS 接口源，无本地文件无需处理

有异常时，上方检测分组标题会显示 ⚠ Spider 资源缺失 N 个（只统计本地 Spider 源；type:1 直连 / 0 XML / 4 目录 / 远程源不参与，不会误报）。

② 成人/短剧/直播检测（手动）

在「检测」卡片里勾选 成人/短剧/直播，点「开始」→ 逐站读 .py 文本，同一遍扫描同时判定三类内容：

  • 成人内容命中的在「成人」列标红 是(检)
  • 短剧类源命中的在「短剧」列标橙 是(检)
  • 直播类源命中的在「直播」列标紫 是(检)

检测素材分源类型自动适配：

  • Spider 源（type 3）：读本地 .py 文本 + 站点名 + ext 字段
  • 直连/XML/目录源（type 0/1/4）：无本地 .py，按 站点名 + ext 字段 判定
  • 深度检测（可选勾选，默认关）：勾上后对 api 为 http(s) 地址的直连站实际拉取一次接口页面内容（移动 UA、8 秒超时、限 256KB、失败静默跳过），把返回文本一并送入关键词匹配——能抓出「站名干净但分类里全是成人内容」的漏网站点。代价是每站一次网络请求，检测明显变慢（串行），建议平时关闭、需要排查时再勾。

成人词表已与「分类词库」统一为单一来源，词条可由用户自行维护（旧的部分易误伤词条已剔除）。

讨厌短剧或直播源？ 检测完成后点底部「禁用短剧」或「禁用直播」，一键把对应类源批量注释禁用（可逆，随时「启用选中」恢复）。也可以先点对应列头把该类源排最前，逐个确认后再操作。

③ URL 可达性检测（手动）

在「检测」卡片里勾选 URL 可达性，点「开始」→ 按 type 分流探测：Spider 源抽取其 .py 里的源地址，直连（type:1）/ XML（0）/ 目录（4）源直接探测其接口地址，TCP + HTTP 双方法：

  • 可达(tcp:443)（绿）/ 不可达（红）/ 无地址可用（灰，如本地 .py 缺失）
  • 不可达只是标记，不会自动禁用——你可以点「可达」列头把不可达排前面，再手动禁用。

「检测」卡片底部是一行共用控制（开始 / 暂停（继续）/ 停止）：勾哪路就跑哪路，两路可同时跑、互不干扰，可随时暂停或停止。检测期间编辑类按钮暂时锁定，「关闭」始终可用。

④ 需要走代理做检测时（🌐 代理服务器）

检测卡片最底部有一行 🌐 代理服务器：[输入框] [🔌 验证] [状态]，「🧰 工具箱 → 网络诊断」页顶部也有同一行（两处共用同一设置，改一处另一处自动同步，关掉程序也记得）：

  1. 在输入框填代理地址，例如 http://127.0.0.1:7890（Clash/V2Ray 的 HTTP 端口）或 socks5://127.0.0.1:7891；留空就是直连（系统里的 HTTP_PROXY 环境变量不会被自动跟随，检测到只会提示你一句）。
  2. 点 🔌 验证 —— 它在后台连一次 Google 首页：能打开就是「✓ 正常」，打不开就告诉你原因（超时 / 被拒 / 地址写错…）。
  3. 如果显示"直连不通 → 代理确实在起作用"，说明这个代理真的在用，最理想；
  4. 如果直连也能打开 Google，只说明代理可用，是否必须由你判断。
  5. 验证通过后，URL 可达性 / 网络体检 / 工具箱各项 / 🩺 源测活连同 py 源自身的请求都会经这个代理出去，直接点「开始」检测即可。

几点要知道的口径：

- 走代理时不再做 TCP 直连（TCP 绕不过代理），URL 可达性只看经代理的 HTTP 是否 2xx/3xx； - 源测速走代理后没有 TCP 兜底，数值就是经代理的 HTTP 延迟； - 网络诊断经代理时本机 DNS 不参与（域名交给代理解析），所以「IP」列为空、结论会写明"经代理"； - 若代理填的是 socks5://：工具自身的检测全都没问题（内置 SOCKS5，免装依赖），但 🩺 源测活用的是 py 源自己的 requests，走 SOCKS5 需要 PySocks——没有它时结果里会 明确提示"仅供参考"，不会假装是死源。想测得准就用代理软件的 HTTP 端口 （Clash 的 127.0.0.1:7890 是混合端口，直接填它即可）。

场景 4：临时停用某个源（不删除）

  1. 选中行 → 点「禁用选中」→ 立即生效（自动备份）。
  2. 该站点在配置里被注释起来，APP 加载时即忽略；列表「禁用」列显示「是」。
  3. 想恢复：选中 →「启用选中」。

被禁用的条目仍处于注释状态，要先启用才能编辑。

场景 5：处理"缺失 .py"的条目

按实际意图三选一：

  1. 源已废弃 → 选中（可多选）→「删除选中」（可同时删掉已不存在的 .py 登记）。
  2. 只是暂时不想用 → 选中 →「禁用选中」。
  3. 文件其实还在，只是文件夹被改名/移动 → 若显示「已找回」，双击该行把 api 改成找回的新路径；或把文件夹改回原名后重新打开列表确认变「正常」。

场景 6：查重 / 去重

  • GUI：表格里右键任意行 → 🔍 查重 查看重复报告；主窗口顶部工具栏的 ♻ 去重（与 ⚙ 管理站点 同排）一键清理重复项（保留首个，不删 .py）。
  • CLI：--check 只报告，--dedup --write 落盘。

判重口径（重要）

不是「name 相同」就算重复，也不是「api 相同」就算重复。 真正的重复只认下面两条：

判定含义处理
key 重复key 是配置主标识，必须唯一 → 结构性冲突去重时删后者
(type + api + jar + ext) 四元组全同功能上就是同一个站点（重复登记）去重时删后者

反过来，以下情况不算重复（属合法配置，查重 / 去重 / 合并都不会碰）：

  • 仅 api 相同、type/ext/jar 不同 —— 多线路共享同一个 spider 类名。典型是 lubin.jar 这类

「多仓聚合 jar」：一个 csp_PanWebShare 类对应 8 个不同的上游站点，靠 ext.site（上游地址） 区分；csp_Bili / csp_XBPQ / csp_Config 同理。

  • name 相同但其它不同 —— 名字只是显示标签，可改、可重名，不参与判重。

一句话：身份 = (type + api + jar + ext) 四元组；key 负责唯一性；name 不参与。 注意 type 也在身份里，且 0 是合法值（XML） —— 显式写 type: 0 的条目不会被当成"没写"而被改写。

「合并导入」用的是同一套口径，所以三处（查重 / 去重 / 合并）结论一致，不会这里重复那里不重复。

场景 7：把另一份配置合并进来（🔀 合并导入）

主窗口工具栏点「🔀 合并导入」。典型用途：换配置时把旧配置的站点连脚本一起搬过来；或把别人分享的一份源并进自己的仓库。

第 1 步 · 选来源（三个页签任选其一）：

来源操作
本地文件「浏览…」选另一份含 sites 的 .json / .jsonc →「解析本地文件」
粘贴文本把配置 JSON 粘进文本框 →「解析粘贴文本」
URL填 http(s):// 地址 →「下载并解析 URL」（github 系地址直连失败会自动走镜像）

第 2 步 · 逐条预览：表格列为 勾选 / 名称 / key / api·类型 / 判定 / 动作。

  • 「判定」告诉你这条为什么这样归类：新增 / 重复(已存在)（功能身份完全相同，默认不勾且锁定）/ 冲突（key 撞车）
  • 「动作」每条可选 新增 / 覆盖 / 跳过；也可用「全部加入」「全部跳过」批量设
  • 底部摘要实时算：「来源共 N 条：将新增 x · 覆盖 y · 跳过 z」
  • 来源里处于禁用态的条目，合并后仍保持禁用

第 3 步 · 点「合并写入」。它会：

  1. 把站点写进当前配置（保留原注释与排版的手术式改写），自动备份；
  2. 自动搬运配套文件：api、jar、ext 里指向的 .py/.js/.drpy/.jar，以及这些文件内部再 require/load/import 的其它文件一并递归搬（深度 ≤ 4）；
  3. 同名安全处理：
  4. 内容相同 → 跳过；
  5. 内容不同 → 默认改名（x.py → x_2.py）并自动改写所有指向它的引用（api / jar / 文件内 import / ext 里的路径），绝不覆盖你已有的文件；逐文件确认框里也可改选「覆盖（先备份）」或「跳过」；
  6. 来源里有 lives（直播源）/ parses（解析源）/ ads（广告拦截）时，会弹出明细清单让你逐条勾选，不会静默并入；ads 按内容并集去重（能拦更多广告，重复项自动跳过）；
  7. 找不到的文件（远程 404 等）会列进「未搬运」清单并提示，不会打断整批导入。

合并完成后弹窗会汇总：新增/覆盖/跳过条数、配套文件 已复制/已跳过/已改名/未找到、镜像加速条数。 若某个要改引用的文件不是 UTF-8（如 GBK），程序宁可这条引用不改，也绝不损坏原文件，并在提示里请你人工核对。

场景 8：管理直播 / 解析 / 广告等其它分区

站点之外的顶层数组（lives 直播源列表、parses 解析接口、ads 广告规则、rules 播放规则、flags、ijk 播放器参数）在 「🧰 工具箱 → 分区管理」 页统一管理。

  1. 打开工具箱，把「功能」下拉切到 分区管理；
  2. 上面会出现若干 Tab（只显示你配置里确实存在的数组，例如 电视直播（lives）、播放规则（rules））；
  3. 每个 Tab 里是一张表：状态 / 名称·标识 / 地址·摘要。选中一行后用按钮操作：
  4. ➕ 新增 —— 弹出一个 JSON 对象编辑器（各分区字段不同，直接编辑最直观），填完点确定；
  5. ✏ 编辑（双击行同样能编辑）—— 整体替换这一条，别的条目和注释都不受影响；
  6. 🗑 删除 —— 会先让你确认；
  7. ↑ 上移 / ↓ 下移 —— 调整顺序（只动启用中的条目）；
  8. 🚫 禁用 / ✓ 启用 —— 「禁用」是把该条注释掉（/ [disabled] … /），宿主程序会忽略它，但内容还留在文件里，随时可恢复；
  9. ↻ 重新载入 —— 重新读盘（期间你在别处改过配置时用）。
  10. 每次操作都会立即写盘并自动备份到配置目录的 backups/，状态栏会告诉你备份文件名。

合并导入时来源里的 lives / parses / ads 也能逐条勾选并入（见场景 7）；而 rules / flags / ijk 目前只能在本页管理——合并导入不会读取它们。

  2. 设备地址填盒子 IP（如 192.168.1.9），端口一般 5555，点 连接并检测；

  4. 点 ＋ 加入仓库目录 把整个仓库扫进清单；要传别的配置就点 ＋ 文件… / ＋ 文件夹…

（不写死 py.json / py/，仓库之外的配置文件照样能传）；

  1. 清单里逐项勾选（默认全勾），点 📤 开始上传；
  2. 结果表逐行看：✓ 成功 / ⏭ 跳过（远端已一样）/ ✗ 失败（后面写原因）/ ⏹ 取消。

常见问题

Q：改坏了怎么回退？ 每次写盘前都会自动备份：py.json.bak.<时间戳>。把配置目录里对应备份改回 py.json 即可。删错的 .py 在 py_trash/ 里。

Q：扫描提示"缺失 .py"但文件明明在？ 多半是 py 文件夹被改名或移动了。先看「资源」列是否显示「已找回」——是则改 api 路径；否则检查配置文件里 api 写的是否是相对路径 ./py/xxx.py。注意直连源（type:1）本来就没有本地 .py，「资源」列显示「直连」属正常。

Q：怎么添加一个不带 .py 的直连 CMS 源？ 主窗口工具栏点「➕ 添加直连」，粘贴 API 地址（如 https://xxx.com/api.php/provide/vod）即可：程序自动推断 type=1、按域名生成 name 与唯一 key，进待注入列表后可像 .py 一样双击改名字，再「💾 写入配置」。CLI 等价：--add-cms <API地址>。

Q：URL 检测显示不可达，但 APP 里能看？ 检测默认走你电脑的直连网络。若你在公司网/校园网、或该源本身需要代理才能用，就会误报。从新版起可以填代理：在检测卡片底部的「🌐 代理服务器」填上你的代理地址、点「🔌 验证」确认能连上 Google 首页，之后所有检测与源测活都会经这个代理出去，误报就没了。它只是提示，不会自动禁用你的源。

Q：填了代理，怎么确认它真的在起作用？ 点「🔌 验证」：它会经代理和不经代理各连一次 Google 首页。若提示"直连不通 → 代理确实在起作用"，说明代理真的在用；若直连也能打开 Google，只说明代理可用。留空输入框 = 直连（系统里的 HTTP_PROXY 环境变量不会被自动跟随，检测到只会在状态栏提示一句）。

Q：检测会很慢吗？ 文件存在性检测秒级；成人检测取决于 .py 数量和大小（一般几秒~十几秒）；URL 检测最慢（每站要联网探测），建议需要时再手动开始，可暂停。

Q：会不会执行我的爬虫代码？ 不会。所有 .py 都只当文本读取，程序从不执行任何爬虫代码。

Q：界面怎么自动变深色了？ 程序跟随系统深浅色：在 Windows 10/11 开启深色主题后启动即为深色界面，切回浅色再启动即恢复，无需任何手动设置。 （注：Win7 版用的是 Qt5 渲染，只跟随系统主题，不支持跟随深浅色切换。）

Q：标题栏里的「v2610041344」是什么？ 版本号，格式为语义化三段式 主.次.修订（如 v1.2.0）。所有窗体（主窗口、各对话框、提示弹窗）标题栏都带这个后缀，一眼就能确认手上是哪一版。

Q：「🧹 剔除失效源」会不会误删我的好源？ 不会。它只认两类明确失效信号：① URL 可达性检测判为「不可达」；②「资源」列显示「缺失」。从没检测过的站点一律不算失效——如果还没跑过测活 / URL 检测，这个动作等于什么都不做。默认动作是「禁用」（随时可用「启用选中」恢复），要真删得在确认框里显式选「删除」，而且只摘配置项、不删 .py。

Q：合并导入会不会覆盖我现有的 .py？ 不会默认覆盖。目标里已有同名文件时：内容相同 → 直接跳过；内容不同 → 默认改名（x.py → x_2.py）并把所有指向它的引用（api / jar / 文件内 import / ext 路径）同步改到新名。只有你在逐文件确认框里主动选「覆盖」，才会先备份（backups/companions/）再覆盖。

Q：Win7 上提示"缺少 xxx.dll"怎么办？ 请用文件名带 -Win7 后缀的那一份（Win7 版按需构建，最新为 源管家 v1.0.1-Win7.exe）。 主程序（Qt6 版，文件名不带后缀）依赖 Python 3.13 / Qt6 的运行库，这两者都要求 Win8 以上，不是打包漏文件。Win7 版走的是 Python 3.9 + Qt5 那一套，才真正支持 Win7；另外确保系统装过 VC++ 运行库（2015-2019）。

Win7 版怎么来 / 怎么打

工程里同一份 injector.py 内含 Qt 绑定兼容层：装得到 PySide6 就走 Qt6，装不到就自动回退 PySide2（Qt5），所以两套 exe 由同一份源码产出。

# 1) 建 Python 3.9 环境（3.9 是微软最后一个支持 Win7 的 Python）
<py39> -m pip install -r requirements-win7.txt

# 2) 一键构建（版本核对 → 纯逻辑测试 + Qt5 GUI 冒烟 → 打包 → 冒烟）
<py39> build_win7.py

# 产出：源管家 v<版本>-Win7.exe（与 Win10+ 版并存，互不覆盖）
# 本版产出：源管家 v1.2.0.exe（Win7 版需专门要求，产出 源管家 v<版本>-Win7.exe）

关于版本号：本版起改用语义化三段式 主版本.次版本.修订号（如 1.2.0），两条流水线识别到该格式直接放行、不再核对日期。 旧「日期 + 时间」YYMMDDHHMM 格式仍然支持（此时强制前 6 位等于今天）；节日特别版这类标记串（如 "2026 国庆特别版"）会被识别为非标准版本号， 打印「⚠️ 非标准版本号（节日特别版），跳过日期核对」并继续。切换版本风格只需改 APP_VERSION 一处，其余无需回滚。

两条构建流水线的关系：

脚本解释器 / Qt产物
build.py3.13 / PySide6源管家 v<版本>.exe
build_win7.py3.9 / PySide2源管家 v<版本>-Win7.exe

两条流水线产出的是同一份 injector.py（内含 Qt 绑定兼容层），功能完全一致；Win7 版用 Qt5 渲染， 不能跟随系统深浅色切换（详见文末 FAQ）。
